## 1. デザインコンセプト

**「ダッシュボード(計器盤)」**をモチーフにしたテーマ。

- ヘッダは車の計器盤を思わせる**パネルネイビー**、主要アクション(給油を記録)は**メーターアンバー**(メーター照明・燃料計の警告灯の色)で、画面内で最も目立たせる
- 燃費などの数値は**メーター表示のように大きく・等幅数字**で見せる
- 背景は明るいライトグレー基調。**直射日光下(給油所)での視認性**を最優先し、淡い色のテキストを多用しない(コントラスト比 4.5:1 以上を原則とする)

### 設計原則(優先順)

1. **記録が最速**: 給油入力は必須2項目(ODO・給油量)+保存で完了(金額は任意)。前回値・今日・満タンONを初期値にし、判断と入力を減らす
2. **片手・親指操作**: 保存ボタン・大ボタン・FAB・タブバーはすべて画面下半分に配置。ヘッダ側には「戻る/キャンセル」など低頻度操作のみ置く
3. **誤記録の防止**: どの画面でも「いま選択中の車両」が見える。入力画面にも対象車両を表示する
4. **警告は出すが止めない**: バリデーションは原則「警告表示(保存可)」。入力の手を止めない(要件 6.1 準拠)

#### 車両写真の上で使う色(5.15)

写真の明暗はユーザーの写真次第で決まるため、**写真の上に置くテキストは専用の色セットに差し替える**(パネル色そのままだと白い車体・空・雪の上でコントラスト不足になる)。

| トークン | 値 | 用途 |
|---|---|---|
| `--c-hero-scrim` | `rgba(31,43,58,.78)` | 写真の上に敷く暗幕(スクリム)。**この不透明度を下回らせない**(5.15.3) |
| `--c-panel-sub-on-photo` | `#C9D6E4` | 写真の上の補助テキスト(写真なし時の `--c-panel-sub` の置き換え) |
| `--c-trend-up-on-photo` | `#7FE7B6` | 写真の上の前回比 ▲良化(写真なし時は `#5DD39E`) |
| `--c-trend-down-on-photo` | `#FFC2C9` | 写真の上の前回比 ▼悪化(写真なし時は `#FF9AA5`) |
| `--c-photo-slot` | `#EEF2F7` | 写真プレースホルダ(サムネ枠)の地色 |

- 白 `#FFFFFF` はスクリム込みで最悪ケースでも 7.0:1 を確保できるため**差し替え不要**(検証は 5.15.3)
- 写真の有無で切り替わるのは**色だけ**。サイズ・配置・文言は変えない(見た目が動かない)

### 使い分けルール

- **アンバー = 「記録する」**: 給油記録CTA・保存ボタン・追加FABに限定。1画面に大きなアンバーは原則1つ
- **ブルー = 「移動・選択」**: リンク、二次ボタン、フィルタ・期間チップの選択状態
- 満タンバッジ=ブルー系 / 部分給油(計算待ち)=グレー系 / 警告=アンバー系(warn) / 削除=レッド

## 3. タイポグラフィ

フォント: システムフォント(追加読み込みなし。オフライン・表示速度優先)

```
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
             "Hiragino Sans", "Noto Sans JP", "Yu Gothic UI", sans-serif;
```

数値(燃費・金額・ODO)は必ず `font-variant-numeric: tabular-nums`(等幅数字)を指定し、桁が揃って読めるようにする。

| トークン | サイズ/行間 | ウェイト | 用途 |
|---|---|---|---|
| `display` | 44px / 1.1 | 700 | ホームの直近燃費(最大表示) |
| `num-lg` | 28px / 1.2 | 700 | 入力欄の数値、詳細画面の燃費 |
| `title` | 18px / 1.4 | 700 | 画面タイトル、カード見出し |
| `body` | 15px / 1.6 | 400 | 本文・リスト主文 |
| `sub` | 13px / 1.5 | 400 | 補助情報(単価・日付・前回値ヒント) |
| `caption` | 11px / 1.4 | 500 | バッジ・タブラベル・単位 |

## 5. 共通コンポーネント

### 5.1 アプリバー(ヘッダ)+ 車両チップ

- 高さ56px、`--c-panel` 背景・白文字。上端はセーフエリア対応
- **車両チップ**: **車両タイプアイコン(車/バイク。5.12参照)**+車両名+下向きシェブロン。**タップで車両切り替えシート(S-11)を開く**。タップ可能に見えるよう半透明白の角丸背景を敷く。アイコンは選択中の車両のタイプに追従して切り替わり、車とバイクがひと目で区別できる
- 一覧系画面(S-01/03/06/07)には車両チップを必ず表示。入力系(S-02/04/05)はヘッダは「✕(キャンセル)+タイトル」とし、対象車両はフォーム先頭行に表示(その場で変更可)
- 車両に依存しない画面(S-08 車両管理 / S-09 設定)はタイトルのみ

### 5.2 タブバー

- 4タブ: **ホーム / 給油(→S-03) / メンテ(→S-06) / 設定(→S-09)**。白背景+上罫線
- アクティブ: ネイビーのアイコン・ラベル+上辺にアンバーのインジケータバー(3px)
- 入力画面(S-02/04/05)ではタブバーを非表示(モーダル的に扱い、誤タップ防止)

### 5.3 ビッグナンバー(燃費表示)

- `display`(44px)+単位(`caption`、`--c-sub`)。「19.2 <small>km/L</small>」
- 直下に補助行(平均燃費・前回差分)。前回比は ▲良化=green / ▼悪化=danger の小バッジ

### 5.4 数値入力フィールド(NumField)

給油入力の中核コンポーネント。

- 構成: ラベル(左上・13px)/ 数値入力(28px・右寄せ)/ 単位サフィックス(km・L・円)
- **必須/任意の表記**: 必須はラベル横に赤の「*」、任意はグレー(`--c-sub`)の小さめテキスト「任意」をラベル横に付ける
- `inputmode="decimal"`(給油量)または `inputmode="numeric"`(ODO・金額)で**テンキーを起動**。`type="text"`+patternではなく `type="number"` 系を基本とする
- **前回値ヒント**: 欄の下に「前回: 34,512 km」等を13pxグレーで表示。ODOはプレースホルダにも前回値を出す
- 自動計算結果(単価)は欄の下に「単価 ≒ 160円/L(自動計算)」とライブ表示。**元値(金額)が未入力の間は計算結果を出さず**、案内文「単価は金額を入力すると自動計算されます(前回 ◯円/L)」を表示。一覧・詳細で値が無い場合は「—」表示
- 警告時: 欄の下に `--c-warn-bg` の角丸チップで警告文(保存はブロックしない)。エラー(必須未入力)は赤文字+保存ボタン無効

### 5.5 満タントグル(Switch)

- 52×32pxのスイッチ+ラベル「満タン」。**初期値ON**
- OFF時は補助文「燃費は次の満タン給油時にまとめて計算されます」を表示し、計算待ちになることを予告する

### 5.6 リスト行(給油履歴・メンテ履歴)

- 高さ64px前後、白背景、行間罫線。行全体がタップ領域(→詳細へ)。右端にシェブロン
- 給油行: 左=日付(2段: 月日+曜日)/ 中=給油量・金額・単価 / 右=**燃費バッジ**
  - 燃費確定: ネイビー地バッジ「19.2 km/L」
  - 計算待ち(部分給油): グレー地バッジ「計算待ち」
- メンテ行: 左=種別アイコン+種別名 / 中=日付・ODO・店舗 / 右=費用

### 5.7 FAB(追加ボタン)

- 56px円形・アンバー・「+」アイコン。右下(タブバーの上、`right:16px / bottom:タブバー+16px`)
- S-03(→給油入力)・S-06(→メンテ入力)に表示

### 5.8 ボトムシート(車両切り替え S-11)

- 画面下から出現、上辺角丸20px、グラバーバー付き。背後は半透明黒(タップで閉じる)
- 車両行(56px): **車両タイプアイコン(車/バイク)**+車両名+補足(メーカー等)、選択中はチェックマーク+ブルー文字
- 最下部に「+ 車両を追加」(→S-08)
- **ヘッダの車両名タップ(1)→車両タップ(2)の2タップで切り替え完了**し自動で閉じる。切替時はトーストで結果を通知

### 5.9 ボタン

| 種類 | 見た目 | 用途 |
|---|---|---|
| Primary(アンバー) | アンバー地+濃色文字、高さ56px、角丸20px | 保存、給油を記録 |
| Secondary(ブルー) | 白地+ブルー罫線・文字 | メンテを記録、CSV書き出し等 |
| Text | ブルー文字のみ | キャンセル、グラフを見る等 |
| Danger | 赤文字(白地)/確認ダイアログ内は赤地 | 削除 |

- 保存ボタンは**フォーム下部に固定(sticky)**し、スクロール位置に関わらず親指で押せる

### 5.10 チップ(フィルタ・期間切替)

- 高さ36px、角丸full。非選択=白地グレー罫線 / 選択=ネイビー地白文字
- S-06の種別フィルタ、S-07の期間切替(直近12回/半年/1年/全期間)に使用。横スクロール可

### 5.11 トースト / 確認ダイアログ

- トースト: 画面下部(タブバー上)に2秒表示。「保存しました(燃費 19.2 km/L)」のように**結果の数値を含めて**通知
- 削除は必ず確認ダイアログ(中央モーダル)。削除ボタンは赤、キャンセルを左・削除を右に配置

### 5.12 車両タイプアイコン(車/バイク)

- 車両タイプ(`car` / `motorcycle`)ごとに専用の**24pxストロークSVGアイコン**を用意する(絵文字は使わない。§7 アイコン方針に統一)
  - 車: ボディ+ホイール2輪の線画
  - バイク: 前後ホイール+フレーム・ハンドルの線画
- 表示箇所: ヘッダの車両チップ(5.1)/ 車両切り替えシートの車両行(5.8)/ S-08車両一覧の行頭 / 入力画面の「対象車両」行。**車両名が表示される場所には必ずタイプアイコンを添える**
- サイズ: チップ内20px / 対象車両行22px / リスト・シート行24px。色は文脈のテキスト色に従う(`currentColor`)

### 5.13 セグメントコントロール(車両タイプ選択)

- S-08 車両登録・編集フォームの「車両タイプ」に使用。**アイコン+ラベル付きの2択(車/バイク)を1タップで選択**
- 形状: 薄グレー(#E7ECF2)のトラック+選択中セグメントは白地・影付き・濃色文字(角丸8px、高さ44px)
- 選択変更時はメーカー候補(5.14)を即時切り替える

### 5.14 メーカー選択(プルダウン+手入力)

- S-08 車両登録・編集フォームのメーカー欄に使用。`<select>`(ネイティブピッカー)を基本とし、**車両タイプに応じて候補を切り替える**:
  - 車: トヨタ / ホンダ / 日産 / マツダ / スバル / 三菱 / スズキ / ダイハツ / レクサス / メルセデス・ベンツ / BMW / フォルクスワーゲン / アウディ / ボルボ
  - バイク: ホンダ / ヤマハ / スズキ / カワサキ / ハーレーダビッドソン / BMW / ドゥカティ / トライアンフ / KTM
- 先頭に「選択してください」(未選択・任意項目のため)、**末尾に「その他(手入力)」**を置き、選択するとメーカー名のテキスト入力欄を直下に表示する
- タイプ切り替えで候補が変わった場合、選択済みメーカーが新候補に無いときは未選択に戻す(誤った組み合わせを残さない)

### 5.15 車両写真(サムネイル / ヒーロー背景 / プレースホルダ)

車両ごとに**写真1枚(任意)**を登録できる。位置づけは「**愛着と識別**」であり、記録の速度に一切影響させない。

**大原則**

1. **写真は装飾情報**: 写真が無くても全機能が同じタップ数で使える。写真を促す割り込み(モーダル・バナー)は出さない
2. **数値の可読性 > 写真の見栄え**: ホームの燃費数値は、どんな写真を入れてもコントラスト比を落とさない(5.15.3 の検証を満たすこと)
3. **レイアウトを動かさない**: 写真の有無・読み込み状態に関わらず、行の高さと文字の開始位置は不変(=リストがガタつかない・誤タップしない)

#### 5.15.1 共通トークン・トリミング方針

| トークン | 値 | 用途 |
|---|---|---|
| `--ph-thumb` | **44px** | 一覧・シートの行頭サムネイル(S-08 / S-11) |
| `--ph-thumb-sm` | 32px | 予備(入力画面の対象車両行・設定の車両行。MVPでは未使用) |
| `--ph-thumb-r` | 8px(`--r-sm`) | サムネイルの角丸 |
| `--ph-thumb-ar` | **1 / 1** | サムネイルのアスペクト比(正方形) |
| `--ph-hero-ar` | **16 / 9**(≒1.78:1) | ヒーロー背景・フォームプレビュー・調整枠のアスペクト比(2026-08-28に 16/7 から変更。理由は下記) |
| `--ph-hero-min-h` | **200px** | 写真ありのヒーロー最低高(床。375px幅では 16:9 = 211px が優先される) |
| `--ph-preview-r` | 12px(`--r-md`) | フォーム内プレビューの角丸 |
| `--ph-badge` | 18px | サムネ右下の車両タイプバッジ(内側アイコン12px) |
| `--ph-fade` | 150ms | 画像フェードイン(`prefers-reduced-motion` 時は 0ms) |
| `--ph-zoom-max` | **3.0** | 拡大の上限(枠いっぱい=1.0 を基準とした倍率。5.15.6) |
| `--ph-pad-bg` | `--c-panel`(`#1F2B3A`) | **縮小したときに生まれる余白の色**(無地ネイビー。5.15.6) |
| `--ph-pad-edge` | `rgba(255,255,255,.14)` | 余白があるとき、写真の外周に入れる内枠1px(暗い写真が余白に溶けないため) |
| `--ph-edit-bg` | `#0F1620` | 写真調整シートの作業面(5.15.7) |
| `--ph-grid` | `rgba(255,255,255,.22)` | 調整枠の三分割グリッド線 |

- **切り抜きの既定は `object-fit: cover` + `object-position: center`**(= 5.15.6 の調整値の既定 `zoom:1 / focus:0.5,0.5` と同じ結果)。ユーザーが調整した場合は **5.15.6 の描画規則**に従う
- 原本は1枚だけ保持し、用途ごとの複数保存はしない(容量とズレ防止)。**調整はトリミング済み画像を作らず、表示時のパラメータとして持つ**(やり直せる・劣化しない)
- **EXIF の回転情報を反映した向きで表示する**(横倒し表示はバグ扱い)
- 表示に必要な解像度: ヒーロー最大 430px幅 × 3dpr ≒ 1290px。**長辺1280px程度に縮小して保持**すれば足りる(それ以上は表示品質に寄与しない)。拡大は最大3倍のため厳密には不足しうるが、**拡大は例外操作**であり、ここを上げると保存容量が全ユーザーに効くので上げない
- サムネイルには `box-shadow: inset 0 0 0 1px rgba(16,30,54,.10)` の内枠を入れる(白い車体が白いカードに溶けないため)

**ヒーロー比率を 16:7 → 16:9 に変えた理由**(2026-08-28)

16:7 は横長すぎて、スマホで撮った標準的な写真(横 4:3)でも**高さの58%しか映らない**。「設定した画像の一部しか表示されない」というフィードバックの主因はここにある。

| 元写真 | 16:7(旧) | **16:9(採用)** | 3:2 | 4:3 |
|---|---|---|---|---|
| 横 4:3(スマホ標準) | 58% | **75%** | 89% | 100% |
| 横 3:2(一眼) | 66% | **84%** | 100% | 100% |
| 横 16:9(動画由来) | 78% | **100%** | 100% | 100% |
| 縦 3:4 | 33% | **42%** | 50% | 56% |

※ 既定(枠いっぱい・中央)のときに見える割合。

- **3:2・4:3 は不採用**。ヒーローが高くなるほど「給油を記録」CTAが下がる。375×667(iPhone SE 相当)では 3:2 で燃費推移カードがフォールド際(残り5px)、4:3 では確実に画面外に出る。**ヒーローが画面高の1/3を超えると、計器盤ではなく写真ビューアに見える**のも避けたい(5.15 大原則1「写真は装飾情報」)
- 16:9 なら 375×667 でも **CTA・二次CTA・燃費推移カードがすべてフォールド内**に収まる(検証は 5.15.3)
- 縦写真(42%)は比率変更だけでは救えない。**縦写真の救済は 5.15.6 の調整UIが担う**。比率変更は「最も件数の多い横4:3で、切れる量を42%→25%に減らす」ための補助策と位置づける
- 例外: **16:9 より横長のパノラマ写真は、旧16:7より横方向の見える量がわずかに減る**(3:1の写真で 76%→59%)。これも調整UIの縮小で全体表示できるため許容する

#### 5.15.2 サムネイル(VehiclePhotoThumb)

```
┌──────────┐
│          │  44×44 / 角丸8px / 1:1 cover
│  写真     │
│        ◍ │ ← 右下に車両タイプバッジ(18px・ネイビー地・白線画・白リング1.5px、2pxはみ出す)
└──────────┘
```

**写真とタイプアイコンの使い分け(排他+バッジで補完)**

| 状態 | 行頭に出すもの |
|---|---|
| 写真あり | **写真サムネイル**(44px)+ 右下に**車両タイプバッジ**(車/バイク) |
| 写真なし | **写真スロット**(44px・`--c-photo-slot` 地・角丸8px)の中央に**車両タイプアイコン24px**(`--c-sub`) |
| 読み込み中 | 写真スロットのみ(アイコンなし・無地)。到着したらフェードイン |

- 写真とタイプアイコンを**横に並べない**(幅を食い、走査が遅くなる)。写真がある行はサムネイルに置き換え、**車/バイクの識別はバッジが担保する**(要件「車・バイクをひと目で識別できること」を写真ありでも維持)
- どの状態でも**リード領域は 44px 固定**。写真の有無で車両名の開始位置がズレないこと
- **ユーザーの調整値(5.15.6)を反映する**: 焦点(`focusX/focusY`)はそのまま適用し、倍率は `max(1, zoom)` にクランプする。つまり **44px枠は常に写真で埋まり、余白は作らない**(識別が目的の小さな枠で余白を作っても情報が減るだけ)。詳細と理由は 5.15.6「2つの枠への適用」
- タイプバッジは装飾のため `aria-hidden`。読み上げ用の種別は行のテキスト/`aria-label` 側で担保する(5.15.5)

#### 5.15.3 ヒーロー背景(S-01)— 可読性の担保

**レイヤー構成(下→上)**

| # | レイヤー | 仕様 |
|---|---|---|
| 0 | **枠の地色** | `--ph-pad-bg`(= `--c-panel` 無地ネイビー)。**縮小して余白が出たときに見える層**(5.15.6) |
| 1 | 車両写真 | ヒーローパネル全面。既定は `cover` / `center`、調整値がある場合は 5.15.6 の描画規則 / `aria-hidden` |
| 2 | **スクリム(暗幕)** | `--c-hero-scrim`(`rgba(31,43,58,.78)`)を**枠の全面に均一**(写真部分も余白部分も同じ)。装飾でグラデーションを重ねてよいが、**合成後の不透明度が .78 を下回る領域を作らない** |
| 3 | テキスト | **§2「車両写真の上で使う色」の色セット**に差し替え+`text-shadow: 0 1px 2px rgba(11,18,26,.55)` |

- スクリムは**均一**にする。「文字のある側だけ濃くする」方式は、フェーズ2でヒーロー内にリマインダー行が増えた時に破綻するため採らない
- **`text-shadow` は保険**。WCAG のコントラスト計算には算入しないため、比率の担保は**スクリムの不透明度だけで**行う
- ヒーローの下角丸(24px)で写真をクリップする。**アプリバーは無地ネイビーのまま**(写真はヒーロー領域のみ。車両チップの可読性と上端の締まりを守る)
- 写真ありのときは `aspect-ratio: --ph-hero-ar` /床として `min-height: --ph-hero-min-h`。テキストが入りきらない場合のみ下に伸びる(文字は絶対に切らない)。テキストは**下寄せ**(上側に写真の抜けを作る)。写真なしのときは現行レイアウト(無地ネイビー・高さはコンテンツ依存)から**一切変えない**
- ヒーローの写真はタップしても何も起きない(記録CTAの近くに新しい操作を増やさない)。**調整導線もホームには置かない**(→ S-08)

**縮小時の余白(レターボックス)の扱い**

ユーザーが枠より小さく縮小した場合(5.15.6)、写真の周りに余白が生まれる。

| 論点 | 決定 |
|---|---|
| 余白の色 | **無地ネイビー `--ph-pad-bg`(= `--c-panel`)で埋める** |
| スクリム | **余白の上にも同じスクリムを均一に敷く**(領域で分岐しない)。ネイビーの上に同系のスクリム .78 を重ねても色はほぼネイビーのままなので、見た目の段差は出ない |
| 可読性 | 余白部分の背景は #1F2B3A 相当で、白文字 **14.2:1** / `--c-panel-sub-on-photo` **10.5:1**。**下表の最悪ケース(真っ白な写真 7.0:1 / 4.8:1)より安全**なので、**コントラスト検証は据え置きでよい** |
| 写真の縁 | 余白があるときのみ、写真の外周に `inset 0 0 0 1px var(--ph-pad-edge)` を入れる(夜の写真・黒い車がネイビーに溶けて「表示されていない」と誤解されるのを防ぐ) |
| 写真の角 | 余白の中の写真は**角丸にしない**(直角)。角丸は枠(ヒーロー下角24px)側の役目 |

- **ぼかし背景(写真を引き伸ばして敷く)は不採用**。理由: ①スクリム .78 の下ではぼかし背景と無地ネイビーがほぼ判別できず、得るものがない ②`backdrop-filter: blur()` は本ガイドで禁止済み(低速端末でホームが重くなる)③書き出し時にぼかし画像を作る案は「原本1枚だけ保持」の原則(5.15.1)に反する
- 余白が大きくなる(縦写真を全体表示した等)ことは**許容する**。ユーザーが明示的に選んだ結果であり、S-08の実寸プレビューで見えている

**「給油を記録」CTAへの影響検証**(設計原則2「片手・親指操作」/ 1「記録が最速」に対する確認)

375×667(iPhone SE 相当・PWA全画面・上部セーフエリア20px・タブバー56px = **フォールド 611px**)で、写真ありホームの積み上げ:

| 要素 | 16:7(旧) | **16:9(採用)** | 3:2(不採用) |
|---|---|---|---|
| ヒーロー高 | 168px | **211px** | 250px |
| 給油を記録(64px) | 260〜324 | **303〜367** | 342〜406 |
| メンテを記録(56px) | 336〜392 | **379〜435** | 418〜474 |
| 燃費推移カード | 408〜524 | **451〜567** | 490〜606(残り5px) |
| 判定 | — | **すべてフォールド内 ✓** | 破綻寸前(アプリバーが厚い端末で画面外) |

- CTAの中心は画面上端から335px = **画面高の50%**。4.7インチ級の親指の自然な可動域内で、下段(タブバー)より上・中段の上端にあたる
- **大きい端末ほど有利**: 430×932 では CTA中心が画面下端から 596px(16:7)→ **542px(16:9)** と**親指に近づく**。ヒーローを高くすることは、大画面での「CTAが遠い」問題の緩和にもなる
- 写真あり(211px)と写真なし(コンテンツ高≒128px)でヒーロー高が変わるため、**車両を切り替えるとCTAが最大83pxずれる**(旧: 40px)。切り替えは S-11 経由の低頻度操作で、直前のタップ位置はシート内(画面下部)のため誤タップにはつながらない。**写真なしユーザーの現行レイアウトは変えない**方を優先し、この差は許容する

**コントラスト検証**(スクリム .78 合成後の背景で算出。写真の各画素は黒〜白の間にあるため、**実際の写真がどうであれ必ずこの範囲に収まる**)

| テキスト | 色 | 最暗ケース(真っ黒な写真) | **最明ケース(真っ白な写真)** | 基準 | 判定 |
|---|---|---|---|---|---|
| 直近の燃費 44px/700 | `#FFFFFF` | 16.1:1 | **7.0:1** | 3:1(大文字) | ✓ |
| ラベル「直近の燃費」12px | `--c-panel-sub-on-photo` | 10.9:1 | **4.8:1** | 4.5:1 | ✓ |
| meta 補助文 13px | `--c-panel-sub-on-photo` | 10.9:1 | **4.8:1** | 4.5:1 | ✓ |
| meta の数値 15px/700 | `#FFFFFF` | 16.1:1 | **7.0:1** | 4.5:1 | ✓ |
| 前回比 ▲良化 15px/700 | `--c-trend-up-on-photo` | 10.8:1 | **4.7:1** | 4.5:1 | ✓ |
| 前回比 ▼悪化 15px/700 | `--c-trend-down-on-photo` | 10.6:1 | **4.6:1** | 4.5:1 | ✓ |

**やってはいけないこと**

- スクリムを薄くする / 写真だけ明るくして「きれいに見せる」(数値の可読性が最優先)
- `backdrop-filter: blur()` を使う(低速端末でホーム表示が重くなる)。**縮小時の余白をぼかし写真で埋めるのも不採用**(理由は上記「縮小時の余白の扱い」)
- 写真の上にアンバーのCTAや警告チップを重ねる(アンバーは明るい色で、写真の上では境界が消える)
- ヒーローの比率を写真の向きに合わせて可変にする(車両を切り替えるたびにCTAの位置が動き、記録の速度と誤タップに直結する。**枠は固定・中身を調整**が本ガイドの方針)

#### 5.15.4 写真ピッカー(S-08 車両編集フォーム)

`<input type="file" accept="image/*">` を隠しておき、見た目はカード状のフィールドで扱う。**`capture` 属性は付けない**(カメラ限定になる端末があり「アルバムから選べない」と誤解される)。文言も「撮影」に寄せず**「写真を選ぶ」**で統一する。

| 状態 | 見た目 | 操作 |
|---|---|---|
| **未設定** | 16:9 の破線枠(1px dashed `#C7D1DC`・角丸12px・地 `--c-photo-slot`)。中央に写真アイコン24px+**「写真を選ぶ」**(ブルーの二次ボタン風)。下に補助文 | **枠全体がタップ領域**(1タップでOSの選択シート) |
| **処理中** | 枠内にスピナー+「写真を準備しています…」。ボタンは無効化 | 操作不可(150ms未満で終わる場合はスピナーを出さない=ちらつき防止) |
| **設定済み** | **ヒーロープレビュー**(16:9・スクリム適用済み・**調整値を反映**・キャプション「ホームでの見え方」)+ その下に**サムネプレビュー行**(44px+「一覧・切り替えでの見え方」) | ①「**位置とサイズを調整**」(ブルー二次・幅いっぱい)→ 5.15.7 のシート ②「**写真を変更**」(ブルー二次)/「**写真を削除**」(赤テキスト) |
| **エラー** | 枠を `--c-warn-bg` 地にし、警告文+「写真を選ぶ」 | 選び直しのみ。ダイアログは出さない(§6 の「手を止めない」に準拠) |

**設定済みのボタン配置**(調整が「写真を選んだ直後に最も起きる操作」になったため2段にする)

```
┌───────────────────────┐
│▓ 写真+スクリム(調整反映)▓│  ← ヒーロープレビュー(タップ不可=ホームと同じ見え方を守る)
└───────────────────────┘
ホームでの見え方
┌──┐
│▣◍│ 一覧・切り替えでの見え方
└──┘
[ ⤢ 位置とサイズを調整 ]        ← 幅いっぱい・48px・ブルー二次(主)
[ 写真を変更 ]   写真を削除      ← 従来行
```

- プレビュー自体は**タップ不可のまま**にする。ここは「ホームでの見え方」を正確に伝える窓であり、操作を載せると WYSIWYG が崩れる(＋「変更」のつもりで調整シートが開く誤操作を防ぐ)
- **調整の発見性を補う一度きりのヒント**: 既定(枠いっぱい)で**写真の70%未満しか映らない**場合のみ、プレビュー直下にグレーのヒントチップを出す。例: 「**縦長の写真のため、一部だけが表示されます**」+ 右に「調整する」。**チップ全体がタップ領域**でシートを開く
  - 判定は `zoomMin < 0.7`(5.15.6)。横4:3(0.75)では出さず、縦写真(0.42)やパノラマで出る
  - 警告色(アンバー)は使わない。**不具合ではなく仕様**であり、放置しても問題ないため(大原則1)
- **スクリムを適用したプレビュー**を見せることが重要。「ホームでは暗く表示される」ことを事前に伝え、"思ったより暗い" というギャップを無くす
- 削除は**確認ダイアログ**(5.11 の流儀: キャンセル左・削除右・赤ボタン)。本文で「**保存すると反映されます。給油・メンテの記録は削除されません**」と伝え、取り消せることも明示する
- 写真の追加・変更・削除**・調整**は**フォームの他項目と同じく「保存する」で確定**する(即時反映しない)。キャンセルで元に戻せる
- **写真を差し替えたら調整値は既定に戻す**(前の写真の倍率・位置を引き継がない。別の構図に他人の調整が乗ると必ず破綻する)

#### 5.15.5 読み込み中・エラー・アクセシビリティ

| 場面 | 挙動 |
|---|---|
| 一覧・シートで未ロード | 写真スロット(無地)を表示し、到着後にフェードイン(`--ph-fade`)。**枠サイズは常に固定**でレイアウトシフト0 |
| ホームで未ロード | 無地ネイビー(=写真なしと同じ)から写真へフェードイン。**スケルトンや点滅は出さない**(燃費数値の読み取りを妨げない) |
| 表示に失敗(画像が壊れている等) | **一覧・ホームでは無言でフォールバック**(タイプアイコン/無地ネイビー)。エラー表示は出さない |
| 同上・S-08 編集フォーム | ここでだけ明示する: 「写真を読み込めませんでした。選び直してください」+「写真を選ぶ」 |
| 保存に失敗(容量不足など) | トースト「写真を保存できませんでした(端末の空き容量をご確認ください)」。他の入力内容は保持する |
| 切り替えシート(S-11) | **画像の取得を待ってシートを開かない**。開くのは常に即時、写真は後から差し込む(2タップの速度を守る) |

- `alt`: 一覧・ヒーローの写真は**装飾**として `alt=""` / `aria-hidden`(車両名テキストが情報を担う。「◯◯の写真」を毎行読み上げさせない)。S-08 のプレビューのみ `alt="登録した写真のプレビュー"`
- 行の `aria-label` には**車両タイプを含める**(例: 「車 ノート に切り替え」)。タイプバッジが視覚のみの情報にならないようにする
- `loading`: 一覧は `lazy`、S-11 シート内は `eager`(数件のみ・開いた瞬間に見える必要がある)。いずれも `decoding="async"`
- 新規アイコン: **写真アイコン**(枠+山と丸の線画)を §7 方針どおり24pxストロークSVGで追加する(絵文字は使わない)。調整シート用に**拡縮アイコン**(斜め両矢印 `⤢`)・**山/大の倍率アイコン**を同方針で追加する

#### 5.15.6 写真の調整(倍率・位置)— 保持する値と描画規則

「設定した画像の一部しか表示されない/縮小と位置調整をしたい」への回答。**トリミング済み画像を作らず、表示パラメータとして持つ**(原本1枚の原則を守り、何度でもやり直せる・再圧縮で劣化しない)。

**保持する値(Vehicle 1件につき1組)**

| 値 | 型・範囲 | 既定値 | 定義 |
|---|---|---|---|
| `zoom` | number / `zoomMin(ヒーロー枠)` 〜 `--ph-zoom-max`(3.0)・小数2桁 | **1.0** | **ヒーロー枠を隙間なく埋める倍率(cover)を 1.0 とした相対倍率**。1未満=縮小(余白が出る)/1超=拡大 |
| `focusX` | number / 0〜1・小数3桁 | **0.5** | 枠に写したい**写真上の点**の横位置(0=左端・1=右端) |
| `focusY` | number / 0〜1・小数3桁 | **0.5** | 同・縦位置(0=上端・1=下端) |

- **既定値 `{1.0, 0.5, 0.5}` は `object-fit: cover` + `object-position: center` と完全に同じ結果**になる。よって**値が未設定(`undefined`)の既存ユーザーは、これまでどおりの見え方のまま**(枠比率が16:9になった分だけ、切れていた部分が"増えて見える"方向にのみ変化する。見えていたものが消えることはない)
- 倍率を**枠に対する相対値(cover=1)**で持つのが要点。写真の実ピクセル数や枠の実寸に依存しないため、**端末幅が違っても・比率の違う枠に流用しても同じ意味**になる
- 焦点を**写真上の正規化座標**で持つのも同じ理由。「枠に対する移動量」で持つと枠ごとに変換が必要になり、破綻する

**描画規則(枠サイズ `Fw×Fh`、写真の自然サイズ `Pw×Ph`)**

```
coverScale   = max(Fw/Pw, Fh/Ph)          枠を埋める倍率
containScale = min(Fw/Pw, Fh/Ph)          全体が収まる倍率
zoomMin      = containScale / coverScale  ← 「全体を表示」の倍率(≦1)
s  = coverScale × zoom                    実際の描画倍率
Dw = Pw × s,  Dh = Ph × s                 描画サイズ

軸ごとに配置(横軸の例。縦軸も同様):
  はみ出す軸 (Dw >  Fw): left = (Fw − Dw) × focusX   ← CSS の object-position: focusX×100% と同一
  収まる軸   (Dw ≦ Fw): left = (Fw − Dw) ÷ 2         ← 中央(= focus 0.5 とみなす)。差分が余白
```

- **はみ出す軸の式は自動的にクランプされる**((Fw−Dw) が負のため、focus 0〜1 の範囲で枠外に隙間が出ない)。「引っぱりすぎて端に白が出る」状態は原理的に発生しない
- **収まる軸では focus を無視して中央**。片方の軸だけ余白が出る中間状態(例: 4:3写真を zoom 0.9)でも規則が1つで済む
- ドラッグ量 Δpx と focus の関係: `Δfocus = −Δpx / (D − F)`(はみ出す軸のみ)。収まる軸はドラッグに反応しない
- 読み込み時に範囲外の値が入っていたら**クランプして描画する**(壊れた値でレイアウトを崩さない)

**2つの枠(ヒーロー16:9・サムネ1:1)への適用 — 基準点だけを共有する**

| 枠 | `focus` | `zoom` | 理由 |
|---|---|---|---|
| ヒーロー(16:9) | **そのまま適用** | **そのまま適用**(余白が出るのを許容) | ここが調整の基準枠。ユーザーが見ながら決めた枠そのもの |
| サムネ(44px 1:1) | **そのまま適用** | **`max(1, zoom)` にクランプ** | 「どこを写したいか(=車の顔)」の意図は共有すべき。一方 **44pxの枠に余白を作ると識別性が落ちるだけ**なので、縮小だけは効かせない |

- 1つの調整で2つの比率をまかなう方針: **倍率は基準枠(ヒーロー)の値、焦点は写真上の点として全枠で共有**。ユーザーには枠ごとの調整をさせない(操作が倍になり、記録アプリの範疇を超える)
- 結果は調整シート内の**44pxプレビューでリアルタイムに確認できる**(拡大しすぎてサムネが意味不明になれば、その場で気づける)
- フォームプレビュー(16:9)はヒーローと同じ枠比率なので**そのまま同じ見え方**になる

#### 5.15.7 写真調整シート(S-08a)

写真ピッカーの「位置とサイズを調整」から開く**全画面シート**。フォーム内インライン編集は採らない: ①スクロール中のフォーム内でドラッグするとページスクロールと競合する ②小さな編集面では指が写真を覆う ③`touch-action: none` を安全にかけられる領域が要る、の3点による。

```
┌──────────────────────────────┐
│ ✕            写真の調整            │ ← 56px・ネイビー・左に✕(低頻度=上段)
├──────────────────────────────┤
│  作業面 --ph-edit-bg                │
│   ┌────────────────────┐        │
│   │   ┆    ┆           │ 16:9枠 │ ← 三分割グリッド(--ph-grid)
│   │┄┄┄┼┄┄┄┄┼┄┄┄┄┄┄┄┄┄┄┄│ 実寸相当│    枠外は作業面色でマスク
│   │   ┆直近の燃費        ┆│        │ ← 文字が乗る位置のゴースト表示
│   │   ┆19.2 km/L        ┆│        │
│   └────────────────────┘        │
│  ドラッグで位置・スライダーで大きさ        │
│  ホームでは全体に暗幕がかかります(数値用)   │
├──────────────────────────────┤
│  大きさ [−]─────●────────[+] 120% │ ← −/+ は44pxタップ
│         ↑全体   ↑枠いっぱい            │    2か所にノッチ+1.0にスナップ
│  [ 全体を表示 ]   [ 枠いっぱいに戻す ]     │ ← 48pxチップ・どちらも位置を中央に戻す
├──────────────────────────────┤
│  ┌──┐ 一覧・切り替えでの見え方           │ ← 44pxサムネを即時反映
│  └──┘                              │
│  [        完了        ]              │ ← アンバー56px・下部固定
│  調整はフォームの「保存する」で確定します      │
└──────────────────────────────┘
```

**操作系の選択: ドラッグ(1本指)+ スライダーを正式仕様、ピンチは補助**

| 操作 | 採否 | 理由 |
|---|---|---|
| **1本指ドラッグ = 移動** | **採用(必須)** | 片手・親指で完結する。写真アプリ共通の作法で説明不要 |
| **スライダー = 拡大縮小** | **採用(必須)** | ①**片手で完結**(ピンチは2本指=両手になりがち)②**縮小できること自体が目に見える**。今回のフィードバックは「縮小できると気づけない」問題でもあるため、UIが能力を語る必要がある ③端(全体表示)とノッチ(枠いっぱい)に**確実に止められる** |
| ピンチ = 拡大縮小 | **補助(任意実装)** | 知っている人には自然なので効くようにする。ただし**これに依存しない**(2本指必須のUIにしない)。実装時は2本指の中点を保持してズームする |
| ダブルタップで全体⇄枠いっぱい | 不採用 | ドラッグ操作中の誤爆が多く、プリセットチップで同じことが1タップでできる |
| 回転・傾き補正 | 不採用(スコープ外) | 記録アプリの範疇を超える。EXIF回転は自動対応済み(5.15.1) |

**プリセット(=リセット手段)**

| チップ | 動作 | 位置 |
|---|---|---|
| **全体を表示** | `zoom = zoomMin(ヒーロー枠)` / `focus = 0.5, 0.5` | 左 |
| **枠いっぱいに戻す** | `zoom = 1.0` / `focus = 0.5, 0.5` = **既定値**(実質のリセット) | 右 |

- **どちらも位置を中央に戻す**。これで「中央に戻す」だけの独立ボタンを置かずに済み、コントロール数を最小化できる(ラベルも状態を表す言葉になっていて意味が伝わる)
- ユーザーの主訴(全体を見たい)は **ピッカーの「位置とサイズを調整」→「全体を表示」→「完了」の3タップ**で解決する

**スライダーの仕様**

- `min = zoomMin`(写真ごとに変わる)/ `max = --ph-zoom-max`(3.0)/ `step = 0.01`。トラック6px・つまみ28px・**タップ領域44px**
- **1.0(枠いっぱい)に ±0.02 でスナップ**する。「余白ゼロぴったり」に戻せないと不満になるため必須
- トラック上に **`zoomMin`(全体)と `1.0`(枠いっぱい)のノッチ**を打ち、ラベルを添える
- 現在値は**%表示**(枠いっぱい=100%)。`zoomMin` に達したときだけ「全体」と表示する
- 両端に **−/+ ボタン(44px・±5%)**。片手での微調整と、後述のキーボード操作の代替を兼ねる

**編集中の見え方(スクリムの扱い)**

- **編集面の写真にはスクリムを掛けない**(素の写真で操作させる)。暗幕越しでは夜間写真・濃色車の輪郭が見えず、位置合わせができないため
- 代わりに **枠の下部に「直近の燃費 19.2 km/L」のゴースト表示**(実際の位置・サイズ、白+`text-shadow`)を重ね、**文字が乗る場所を避けて構図を決められる**ようにする。これは装飾のため `aria-hidden`
- 枠の下に注記「**ホームでは全体に暗幕がかかります(数値を読みやすくするため)**」を置く
- **本番の見え方(スクリム込み)は完了後のフォームプレビューで確認**できる。既存の2段プレビュー(ホーム/一覧)の流儀はそのまま維持する
- 縮小して余白が出た状態は、**作業面ではなくヒーローと同じネイビー**で描く(完了後と同じ見え方にする)

**確定・破棄**

| 操作 | 挙動 |
|---|---|
| **完了**(アンバー56px・下部固定) | 調整値をフォームの保留状態に反映してシートを閉じる。**DBへの保存はフォームの「保存する」**(5.15.4 と同じ) |
| **✕**(ヘッダ左) | 変更がなければ即閉じる。**変更がある場合のみ**確認ダイアログ「調整を破棄しますか?」(キャンセル左/破棄右・赤。5.11 の流儀)。数十秒の操作を無言で捨てないため、ここは例外的にダイアログを使う |
| 背景タップ | シートは全画面のため該当なし(誤って閉じない) |
| 共通 | **シートを開いている間もフォームの入力内容は保持する**(戻ったときに車両名などが消えない)。シート表示中はタブバー非表示(S-02 と同じモーダル扱い) |

**アクセシビリティ・モーション**

- スライダーは `<input type="range">`。`aria-label="写真の大きさ"` / `aria-valuetext` は「120%」「全体」のように**人が読む文字列**で返す
- **ドラッグの代替**: 編集枠をフォーカス可能にし、**矢印キーで焦点を1%ずつ移動**(Shiftで10%)。加えて、位置調整ができない環境でも**「全体を表示」だけで主目的(全体が見える)は達成できる**ことを担保とする
- ドラッグ中は編集枠に `touch-action: none`(ページスクロールとの競合防止)。ドラッグ開始で**グリッド線を濃く**し、指を離すと戻す(200ms)
- `prefers-reduced-motion: reduce` ではシートのスライドイン・グリッドの濃淡変化を無効化する(倍率・位置の追従自体はアニメーションではないので影響なし)
- 44pxサムネプレビューは**シート内でリアルタイム更新**する(拡大しすぎたときに気づける唯一の場所)

## 7. モーション・その他

- 画面遷移: フェード+わずかな上方向スライド(150ms)。ボトムシートは下からスライド(200ms)。過剰なアニメーションは使わない
- 車両写真の到着: 不透明度のみのフェードイン150ms(`--ph-fade`)。拡大・スライドは付けない(枠が動くとタップを外す)。`prefers-reduced-motion: reduce` では即時表示
- ダークモード: MVPでは対応しない(屋外視認性優先のライト固定)。フェーズ2以降で検討
- アイコン: 24pxストロークアイコン(Feather系のシンプルな線画)をインラインSVGで使用。**絵文字はUIに使用しない**(OS間で見た目が変わり、計器盤テーマの統一感を損なうため)。車両タイプアイコン(車/バイク)・写真アイコン(5.15)も同方針のSVG線画で統一する(5.12)
