## 1. デザインコンセプト

**「ダッシュボード(計器盤)」**をモチーフにしたテーマ。

- ヘッダは車の計器盤を思わせる**パネルネイビー**、主要アクション(給油を記録)は**メーターアンバー**(メーター照明・燃料計の警告灯の色)で、画面内で最も目立たせる
- 燃費などの数値は**メーター表示のように大きく・等幅数字**で見せる
- 背景は明るいライトグレー基調。**直射日光下(給油所)での視認性**を最優先し、淡い色のテキストを多用しない(コントラスト比 4.5:1 以上を原則とする)

### 設計原則(優先順)

1. **記録が最速**: 給油入力は必須2項目(ODO・給油量)+保存で完了(金額は任意)。前回値・今日・満タンONを初期値にし、判断と入力を減らす
2. **片手・親指操作**: 保存ボタン・大ボタン・FAB・タブバーはすべて画面下半分に配置。ヘッダ側には「戻る/キャンセル」など低頻度操作のみ置く
3. **誤記録の防止**: どの画面でも「いま選択中の車両」が見える。入力画面にも対象車両を表示する
4. **警告は出すが止めない**: バリデーションは原則「警告表示(保存可)」。入力の手を止めない(要件 6.1 準拠)

#### 車両写真の上で使う色(5.15)

写真の明暗はユーザーの写真次第で決まるため、**写真の上に置くテキストは専用の色セットに差し替える**(パネル色そのままだと白い車体・空・雪の上でコントラスト不足になる)。

| トークン | 値 | 用途 |
|---|---|---|
| `--c-hero-scrim` | `rgba(31,43,58,.78)` | 写真の上に敷く暗幕(スクリム)。**この不透明度を下回らせない**(5.15.3) |
| `--c-panel-sub-on-photo` | `#C9D6E4` | 写真の上の補助テキスト(写真なし時の `--c-panel-sub` の置き換え) |
| `--c-trend-up-on-photo` | `#7FE7B6` | 写真の上の前回比 ▲良化(写真なし時は `#5DD39E`) |
| `--c-trend-down-on-photo` | `#FFC2C9` | 写真の上の前回比 ▼悪化(写真なし時は `#FF9AA5`) |
| `--c-photo-slot` | `#EEF2F7` | 写真プレースホルダ(サムネ枠)の地色 |

- 白 `#FFFFFF` はスクリム込みで最悪ケースでも 7.0:1 を確保できるため**差し替え不要**(検証は 5.15.3)
- 写真の有無で切り替わるのは**色だけ**。サイズ・配置・文言は変えない(見た目が動かない)

### 使い分けルール

- **アンバー = 「記録する」**: 給油記録CTA・保存ボタン・追加FABに限定。1画面に大きなアンバーは原則1つ
- **ブルー = 「移動・選択」**: リンク、二次ボタン、フィルタ・期間チップの選択状態
- 満タンバッジ=ブルー系 / 部分給油(計算待ち)=グレー系 / 警告=アンバー系(warn) / 削除=レッド

## 3. タイポグラフィ

フォント: システムフォント(追加読み込みなし。オフライン・表示速度優先)

```
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
             "Hiragino Sans", "Noto Sans JP", "Yu Gothic UI", sans-serif;
```

数値(燃費・金額・ODO)は必ず `font-variant-numeric: tabular-nums`(等幅数字)を指定し、桁が揃って読めるようにする。

| トークン | サイズ/行間 | ウェイト | 用途 |
|---|---|---|---|
| `display` | 44px / 1.1 | 700 | ホームの直近燃費(最大表示) |
| `num-lg` | 28px / 1.2 | 700 | 入力欄の数値、詳細画面の燃費 |
| `title` | 18px / 1.4 | 700 | 画面タイトル、カード見出し |
| `body` | 15px / 1.6 | 400 | 本文・リスト主文 |
| `sub` | 13px / 1.5 | 400 | 補助情報(単価・日付・前回値ヒント) |
| `caption` | 11px / 1.4 | 500 | バッジ・タブラベル・単位 |

## 5. 共通コンポーネント

### 5.1 アプリバー(ヘッダ)+ 車両チップ

- 高さ56px、`--c-panel` 背景・白文字。上端はセーフエリア対応
- **車両チップ**: **車両タイプアイコン(車/バイク。5.12参照)**+車両名+下向きシェブロン。**タップで車両切り替えシート(S-11)を開く**。タップ可能に見えるよう半透明白の角丸背景を敷く。アイコンは選択中の車両のタイプに追従して切り替わり、車とバイクがひと目で区別できる
- 一覧系画面(S-01/03/06/07)には車両チップを必ず表示。入力系(S-02/04/05)はヘッダは「✕(キャンセル)+タイトル」とし、対象車両はフォーム先頭行に表示(その場で変更可)
- 車両に依存しない画面(S-08 車両管理 / S-09 設定)はタイトルのみ

### 5.2 タブバー

- 4タブ: **ホーム / 給油(→S-03) / メンテ(→S-06) / 設定(→S-09)**。白背景+上罫線
- アクティブ: ネイビーのアイコン・ラベル+上辺にアンバーのインジケータバー(3px)
- 入力画面(S-02/04/05)ではタブバーを非表示(モーダル的に扱い、誤タップ防止)

### 5.3 ビッグナンバー(燃費表示)

- `display`(44px)+単位(`caption`、`--c-sub`)。「19.2 <small>km/L</small>」
- 直下に補助行(平均燃費・前回差分)。前回比は ▲良化=green / ▼悪化=danger の小バッジ

### 5.4 数値入力フィールド(NumField)

給油入力の中核コンポーネント。

- 構成: ラベル(左上・13px)/ 数値入力(28px・右寄せ)/ 単位サフィックス(km・L・円)
- **必須/任意の表記**: 必須はラベル横に赤の「*」、任意はグレー(`--c-sub`)の小さめテキスト「任意」をラベル横に付ける
- `inputmode="decimal"`(給油量)または `inputmode="numeric"`(ODO・金額)で**テンキーを起動**。`type="text"`+patternではなく `type="number"` 系を基本とする
- **前回値ヒント**: 欄の下に「前回: 34,512 km」等を13pxグレーで表示。ODOはプレースホルダにも前回値を出す
- 自動計算結果(単価)は欄の下に「単価 ≒ 160円/L(自動計算)」とライブ表示。**元値(金額)が未入力の間は計算結果を出さず**、案内文「単価は金額を入力すると自動計算されます(前回 ◯円/L)」を表示。一覧・詳細で値が無い場合は「—」表示
- 警告時: 欄の下に `--c-warn-bg` の角丸チップで警告文(保存はブロックしない)。エラー(必須未入力)は赤文字+保存ボタン無効

### 5.5 満タントグル(Switch)

- 52×32pxのスイッチ+ラベル「満タン」。**初期値ON**
- OFF時は補助文「燃費は次の満タン給油時にまとめて計算されます」を表示し、計算待ちになることを予告する

### 5.6 リスト行(給油履歴・メンテ履歴)

- 高さ64px前後、白背景、行間罫線。行全体がタップ領域(→詳細へ)。右端にシェブロン
- 給油行: 左=日付(2段: 月日+曜日)/ 中=給油量・金額・単価 / 右=**燃費バッジ**
  - 燃費確定: ネイビー地バッジ「19.2 km/L」
  - 計算待ち(部分給油): グレー地バッジ「計算待ち」
- メンテ行: 左=種別アイコン+種別名 / 中=日付・ODO・店舗 / 右=費用

### 5.7 FAB(追加ボタン)

- 56px円形・アンバー・「+」アイコン。右下(タブバーの上、`right:16px / bottom:タブバー+16px`)
- S-03(→給油入力)・S-06(→メンテ入力)に表示

### 5.8 ボトムシート(車両切り替え S-11)

- 画面下から出現、上辺角丸20px、グラバーバー付き。背後は半透明黒(タップで閉じる)
- 車両行(56px): **車両タイプアイコン(車/バイク)**+車両名+補足(メーカー等)、選択中はチェックマーク+ブルー文字
- 最下部に「+ 車両を追加」(→S-08)
- **ヘッダの車両名タップ(1)→車両タップ(2)の2タップで切り替え完了**し自動で閉じる。切替時はトーストで結果を通知

### 5.9 ボタン

| 種類 | 見た目 | 用途 |
|---|---|---|
| Primary(アンバー) | アンバー地+濃色文字、高さ56px、角丸20px | 保存、給油を記録 |
| Secondary(ブルー) | 白地+ブルー罫線・文字 | メンテを記録、CSV書き出し等 |
| Text | ブルー文字のみ | キャンセル、グラフを見る等 |
| Danger | 赤文字(白地)/確認ダイアログ内は赤地 | 削除 |

- 保存ボタンは**フォーム下部に固定(sticky)**し、スクロール位置に関わらず親指で押せる

### 5.10 チップ(フィルタ・期間切替)

- 高さ36px、角丸full。非選択=白地グレー罫線 / 選択=ネイビー地白文字
- S-06の種別フィルタ、S-07の期間切替(直近12回/半年/1年/全期間)に使用。横スクロール可

### 5.11 トースト / 確認ダイアログ

- トースト: 画面下部(タブバー上)に2秒表示。「保存しました(燃費 19.2 km/L)」のように**結果の数値を含めて**通知
- 削除は必ず確認ダイアログ(中央モーダル)。削除ボタンは赤、キャンセルを左・削除を右に配置

### 5.12 車両タイプアイコン(車/バイク)

- 車両タイプ(`car` / `motorcycle`)ごとに専用の**24pxストロークSVGアイコン**を用意する(絵文字は使わない。§7 アイコン方針に統一)
  - 車: ボディ+ホイール2輪の線画
  - バイク: 前後ホイール+フレーム・ハンドルの線画
- 表示箇所: ヘッダの車両チップ(5.1)/ 車両切り替えシートの車両行(5.8)/ S-08車両一覧の行頭 / 入力画面の「対象車両」行。**車両名が表示される場所には必ずタイプアイコンを添える**
- サイズ: チップ内20px / 対象車両行22px / リスト・シート行24px。色は文脈のテキスト色に従う(`currentColor`)

### 5.13 セグメントコントロール(車両タイプ選択)

- S-08 車両登録・編集フォームの「車両タイプ」に使用。**アイコン+ラベル付きの2択(車/バイク)を1タップで選択**
- 形状: 薄グレー(#E7ECF2)のトラック+選択中セグメントは白地・影付き・濃色文字(角丸8px、高さ44px)
- 選択変更時はメーカー候補(5.14)を即時切り替える

### 5.14 メーカー選択(プルダウン+手入力)

- S-08 車両登録・編集フォームのメーカー欄に使用。`<select>`(ネイティブピッカー)を基本とし、**車両タイプに応じて候補を切り替える**:
  - 車: トヨタ / ホンダ / 日産 / マツダ / スバル / 三菱 / スズキ / ダイハツ / レクサス / メルセデス・ベンツ / BMW / フォルクスワーゲン / アウディ / ボルボ
  - バイク: ホンダ / ヤマハ / スズキ / カワサキ / ハーレーダビッドソン / BMW / ドゥカティ / トライアンフ / KTM
- 先頭に「選択してください」(未選択・任意項目のため)、**末尾に「その他(手入力)」**を置き、選択するとメーカー名のテキスト入力欄を直下に表示する
- タイプ切り替えで候補が変わった場合、選択済みメーカーが新候補に無いときは未選択に戻す(誤った組み合わせを残さない)

### 5.15 車両写真(サムネイル / ヒーロー背景 / プレースホルダ)

車両ごとに**写真1枚(任意)**を登録できる。位置づけは「**愛着と識別**」であり、記録の速度に一切影響させない。

**大原則**

1. **写真は装飾情報**: 写真が無くても全機能が同じタップ数で使える。写真を促す割り込み(モーダル・バナー)は出さない
2. **数値の可読性 > 写真の見栄え**: ホームの燃費数値は、どんな写真を入れてもコントラスト比を落とさない(5.15.3 の検証を満たすこと)
3. **レイアウトを動かさない**: 写真の有無・読み込み状態に関わらず、行の高さと文字の開始位置は不変(=リストがガタつかない・誤タップしない)

#### 5.15.1 共通トークン・トリミング方針

| トークン | 値 | 用途 |
|---|---|---|
| `--ph-thumb` | **44px** | 一覧・シートの行頭サムネイル(S-08 / S-11) |
| `--ph-thumb-sm` | 32px | 予備(入力画面の対象車両行・設定の車両行。MVPでは未使用) |
| `--ph-thumb-r` | 8px(`--r-sm`) | サムネイルの角丸 |
| `--ph-thumb-ar` | **1 / 1** | サムネイルのアスペクト比(正方形) |
| `--ph-hero-ar` | **16 / 7**(≒2.29:1) | ヒーロー背景・フォームプレビューのアスペクト比 |
| `--ph-hero-min-h` | 168px | 写真ありのヒーロー最低高(375px幅で 16:7 ≒ 164px 相当) |
| `--ph-preview-r` | 12px(`--r-md`) | フォーム内プレビューの角丸 |
| `--ph-badge` | 18px | サムネ右下の車両タイプバッジ(内側アイコン12px) |
| `--ph-fade` | 150ms | 画像フェードイン(`prefers-reduced-motion` 時は 0ms) |

- **切り抜きは常に `object-fit: cover` + `object-position: center`**。原本は1枚だけ保持し、用途ごとの複数保存はしない(容量とズレ防止)
- **EXIF の回転情報を反映した向きで表示する**(横倒し表示はバグ扱い)
- 表示に必要な解像度: ヒーロー最大 430px幅 × 3dpr ≒ 1290px。**長辺1280px程度に縮小して保持**すれば足りる(それ以上は表示品質に寄与しない)
- サムネイルには `box-shadow: inset 0 0 0 1px rgba(16,30,54,.10)` の内枠を入れる(白い車体が白いカードに溶けないため)

#### 5.15.2 サムネイル(VehiclePhotoThumb)

```
┌──────────┐
│          │  44×44 / 角丸8px / 1:1 cover
│  写真     │
│        ◍ │ ← 右下に車両タイプバッジ(18px・ネイビー地・白線画・白リング1.5px、2pxはみ出す)
└──────────┘
```

**写真とタイプアイコンの使い分け(排他+バッジで補完)**

| 状態 | 行頭に出すもの |
|---|---|
| 写真あり | **写真サムネイル**(44px)+ 右下に**車両タイプバッジ**(車/バイク) |
| 写真なし | **写真スロット**(44px・`--c-photo-slot` 地・角丸8px)の中央に**車両タイプアイコン24px**(`--c-sub`) |
| 読み込み中 | 写真スロットのみ(アイコンなし・無地)。到着したらフェードイン |

- 写真とタイプアイコンを**横に並べない**(幅を食い、走査が遅くなる)。写真がある行はサムネイルに置き換え、**車/バイクの識別はバッジが担保する**(要件「車・バイクをひと目で識別できること」を写真ありでも維持)
- どの状態でも**リード領域は 44px 固定**。写真の有無で車両名の開始位置がズレないこと
- タイプバッジは装飾のため `aria-hidden`。読み上げ用の種別は行のテキスト/`aria-label` 側で担保する(5.15.5)

#### 5.15.3 ヒーロー背景(S-01)— 可読性の担保

**レイヤー構成(下→上)**

| # | レイヤー | 仕様 |
|---|---|---|
| 1 | 車両写真 | ヒーローパネル全面。`object-fit: cover` / `object-position: center` / `aria-hidden` |
| 2 | **スクリム(暗幕)** | `--c-hero-scrim`(`rgba(31,43,58,.78)`)を**全面に均一**。装飾でグラデーションを重ねてよいが、**合成後の不透明度が .78 を下回る領域を作らない** |
| 3 | テキスト | **§2「車両写真の上で使う色」の色セット**に差し替え+`text-shadow: 0 1px 2px rgba(11,18,26,.55)` |

- スクリムは**均一**にする。「文字のある側だけ濃くする」方式は、フェーズ2でヒーロー内にリマインダー行が増えた時に破綻するため採らない
- **`text-shadow` は保険**。WCAG のコントラスト計算には算入しないため、比率の担保は**スクリムの不透明度だけで**行う
- ヒーローの下角丸(24px)で写真をクリップする。**アプリバーは無地ネイビーのまま**(写真はヒーロー領域のみ。車両チップの可読性と上端の締まりを守る)
- 写真ありのときは `min-height: --ph-hero-min-h`、テキストは**下寄せ**(上側に写真の抜けを作る)。写真なしのときは現行レイアウト(無地ネイビー・高さはコンテンツ依存)から**一切変えない**
- ヒーローの写真はタップしても何も起きない(記録CTAの近くに新しい操作を増やさない)

**コントラスト検証**(スクリム .78 合成後の背景で算出。写真の各画素は黒〜白の間にあるため、**実際の写真がどうであれ必ずこの範囲に収まる**)

| テキスト | 色 | 最暗ケース(真っ黒な写真) | **最明ケース(真っ白な写真)** | 基準 | 判定 |
|---|---|---|---|---|---|
| 直近の燃費 44px/700 | `#FFFFFF` | 16.1:1 | **7.0:1** | 3:1(大文字) | ✓ |
| ラベル「直近の燃費」12px | `--c-panel-sub-on-photo` | 10.9:1 | **4.8:1** | 4.5:1 | ✓ |
| meta 補助文 13px | `--c-panel-sub-on-photo` | 10.9:1 | **4.8:1** | 4.5:1 | ✓ |
| meta の数値 15px/700 | `#FFFFFF` | 16.1:1 | **7.0:1** | 4.5:1 | ✓ |
| 前回比 ▲良化 15px/700 | `--c-trend-up-on-photo` | 10.8:1 | **4.7:1** | 4.5:1 | ✓ |
| 前回比 ▼悪化 15px/700 | `--c-trend-down-on-photo` | 10.6:1 | **4.6:1** | 4.5:1 | ✓ |

> 参考: 既存色のまま写真に載せると `--c-panel-sub` は 3.6:1、`#5DD39E`(▲)は 3.8:1、`#FF9AA5`(▼)は 3.5:1 まで落ちる。**色セットの差し替えは必須**。

**やってはいけないこと**

- スクリムを薄くする / 写真だけ明るくして「きれいに見せる」(数値の可読性が最優先)
- `backdrop-filter: blur()` を全面に使う(低速端末でホーム表示が重くなる。ぼかしを使うなら写真書き出し時に済ませる)
- 写真の上にアンバーのCTAや警告チップを重ねる(アンバーは明るい色で、写真の上では境界が消える)

#### 5.15.4 写真ピッカー(S-08 車両編集フォーム)

`<input type="file" accept="image/*">` を隠しておき、見た目はカード状のフィールドで扱う。**`capture` 属性は付けない**(カメラ限定になる端末があり「アルバムから選べない」と誤解される)。文言も「撮影」に寄せず**「写真を選ぶ」**で統一する。

| 状態 | 見た目 | 操作 |
|---|---|---|
| **未設定** | 16:7 の破線枠(1px dashed `#C7D1DC`・角丸12px・地 `--c-photo-slot`)。中央に写真アイコン24px+**「写真を選ぶ」**(ブルーの二次ボタン風)。下に補助文 | **枠全体がタップ領域**(1タップでOSの選択シート) |
| **処理中** | 枠内にスピナー+「写真を準備しています…」。ボタンは無効化 | 操作不可(150ms未満で終わる場合はスピナーを出さない=ちらつき防止) |
| **設定済み** | **ヒーロープレビュー**(16:7・スクリム適用済み・キャプション「ホームでの見え方」)+ その下に**サムネプレビュー行**(44px+「一覧・切り替えでの見え方」) | 下に「**写真を変更**」(ブルー二次)/「**写真を削除**」(赤テキスト) |
| **エラー** | 枠を `--c-warn-bg` 地にし、警告文+「写真を選ぶ」 | 選び直しのみ。ダイアログは出さない(§6 の「手を止めない」に準拠) |

- **スクリムを適用したプレビュー**を見せることが重要。「ホームでは暗く表示される」ことを事前に伝え、"思ったより暗い" というギャップを無くす
- 削除は**確認ダイアログ**(5.11 の流儀: キャンセル左・削除右・赤ボタン)。本文で「**保存すると反映されます。給油・メンテの記録は削除されません**」と伝え、取り消せることも明示する
- 写真の追加・変更・削除は**フォームの他項目と同じく「保存する」で確定**する(即時反映しない)。キャンセルで元に戻せる

#### 5.15.5 読み込み中・エラー・アクセシビリティ

| 場面 | 挙動 |
|---|---|
| 一覧・シートで未ロード | 写真スロット(無地)を表示し、到着後にフェードイン(`--ph-fade`)。**枠サイズは常に固定**でレイアウトシフト0 |
| ホームで未ロード | 無地ネイビー(=写真なしと同じ)から写真へフェードイン。**スケルトンや点滅は出さない**(燃費数値の読み取りを妨げない) |
| 表示に失敗(画像が壊れている等) | **一覧・ホームでは無言でフォールバック**(タイプアイコン/無地ネイビー)。エラー表示は出さない |
| 同上・S-08 編集フォーム | ここでだけ明示する: 「写真を読み込めませんでした。選び直してください」+「写真を選ぶ」 |
| 保存に失敗(容量不足など) | トースト「写真を保存できませんでした(端末の空き容量をご確認ください)」。他の入力内容は保持する |
| 切り替えシート(S-11) | **画像の取得を待ってシートを開かない**。開くのは常に即時、写真は後から差し込む(2タップの速度を守る) |

- `alt`: 一覧・ヒーローの写真は**装飾**として `alt=""` / `aria-hidden`(車両名テキストが情報を担う。「◯◯の写真」を毎行読み上げさせない)。S-08 のプレビューのみ `alt="登録した写真のプレビュー"`
- 行の `aria-label` には**車両タイプを含める**(例: 「車 ノート に切り替え」)。タイプバッジが視覚のみの情報にならないようにする
- `loading`: 一覧は `lazy`、S-11 シート内は `eager`(数件のみ・開いた瞬間に見える必要がある)。いずれも `decoding="async"`
- 新規アイコン: **写真アイコン**(枠+山と丸の線画)を §7 方針どおり24pxストロークSVGで追加する(絵文字は使わない)

## 6. バリデーション表示ポリシー

| 種類 | 表示 | 保存 |
|---|---|---|
| 必須未入力(ODO・給油量。金額は任意) | 保存ボタンを無効化(グレー)+ボタン下に「あと◯項目」 | 不可 |
| ODOが前回より小さい | 欄下に警告チップ「前回(34,512km)より小さい値です」 | **可**(要件6.1) |
| 給油量がタンク容量超過 | 欄下に警告チップ | 可 |
| 算出燃費が1〜60km/L範囲外 | 保存前に警告チップ「燃費が◯km/Lになります。入力をご確認ください」 | 可 |

## 7. モーション・その他

- 画面遷移: フェード+わずかな上方向スライド(150ms)。ボトムシートは下からスライド(200ms)。過剰なアニメーションは使わない
- 車両写真の到着: 不透明度のみのフェードイン150ms(`--ph-fade`)。拡大・スライドは付けない(枠が動くとタップを外す)。`prefers-reduced-motion: reduce` では即時表示
- ダークモード: MVPでは対応しない(屋外視認性優先のライト固定)。フェーズ2以降で検討
- アイコン: 24pxストロークアイコン(Feather系のシンプルな線画)をインラインSVGで使用。**絵文字はUIに使用しない**(OS間で見た目が変わり、計器盤テーマの統一感を損なうため)。車両タイプアイコン(車/バイク)・写真アイコン(5.15)も同方針のSVG線画で統一する(5.12)
