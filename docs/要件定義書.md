# 車・バイク メンテナンス記録・燃費計算アプリ 要件定義書

- 作成日: 2026-07-03
- 作成者: product-planner
- ステータス: **確定(2026-07-03)** ※未決事項はユーザー回答により解消(「10. 決定事項」参照)

---

## 1. アプリの目的

自分の**車・バイク**の「給油」と「メンテナンス」の記録を、給油所や整備工場のその場でスマホからサッと入力でき、
燃費(満タン法)の自動計算とメンテナンス履歴の一元管理ができるアプリ。
車とバイクは同じ「車両」として扱い、給油記録・燃費計算(満タン法)・メンテナンス記録・リマインダーのロジックは共通とする。

### 解決したい課題
- 給油レシートや手帳での記録は続かない・計算が面倒
- オイル交換や車検の「前回いつ・何kmでやったか」が思い出せない
- 燃費の変化(悪化)に気づけない

### ゴール
- 給油記録の入力が **30秒以内・最小タップ数** で完了する
- 給油記録から燃費が **自動計算** され、推移が見える
- メンテナンス履歴が車両ごとに時系列で一覧できる

## 2. ターゲットユーザー

| 項目 | 内容 |
|---|---|
| 主ユーザー | 開発者本人(個人利用) |
| 利用シーン | 給油所での給油直後、整備工場・ディーラーでの作業後、自宅での振り返り |
| 利用端末 | スマートフォン(**iPhone・Android の両方を使用**。同一URLのPWAを両OSからホーム画面追加して利用)。PCからの閲覧は副次的 |
| 管理台数 | **2台以上**(複数車両の管理はMVPに含める)。**車・バイクの混在管理に対応** |
| 利用頻度 | 給油: 週1〜月2回程度 / メンテ記録: 月1回以下 / 閲覧: 随時 |
| 将来 | 家族・知人への展開は将来検討(MVPでは考慮しない) |

## 3. 機能一覧

優先度定義:
- **P0**: MVPに必須。これが無いとアプリの価値が成立しない
- **P1**: MVPに含めたい。日常利用の快適さに直結
- **P2**: MVP後の第1拡張(フェーズ2)
- **P3**: 将来拡張(フェーズ3以降)

### 3.1 MVP(フェーズ1)

| # | 機能 | 優先度 | 概要 |
|---|---|---|---|
| F-01 | 車両登録 | P0 | 車両タイプ(**車/バイク**)・車両名・初期走行距離などを登録(複数台の登録が可能)。メーカーはタイプに応じた主要メーカーのプルダウンから選択可(「その他(手入力)」あり) |
| F-14 | 複数車両の管理 | P0 | 車両の追加・編集・切り替え。記録・集計・グラフを車両ごとに分離。**選択中の車両**に対して記録を入力する(ユーザー回答により2台以上を管理するためMVPに繰り上げ) |
| F-02 | 給油記録の入力 | P0 | 選択中の車両に対し、日付・ODO・給油量・金額(**任意**。総額入力が既定、入力時のみ単価を自動計算)・満タンか否かを入力。**必須はODO・給油量の2項目のみ**(必須2項目化により30秒以内の入力完了がさらに容易になる) |

| F-06 | メンテナンス履歴一覧 | P0 | 種別フィルタ付きの時系列一覧 |

| F-09 | 燃費推移グラフ | P1 | 折れ線グラフ(直近12回/期間指定)。平均燃費ライン付き |
| F-10 | 入力の手軽さ支援 | P1 | 前回値の初期表示(給油所名・ODOプレースホルダ)、日付は今日を初期値、数値キーパッド起動、満タンON初期値、対象車両は選択中の車両を初期値、**よく使う給油所のクイック選択(最大3件、使用頻度順)** |

## 4. 画面一覧

スマホ縦画面前提。画面下部に固定タブバー(ホーム / 給油 / メンテ / 設定)を置き、主要画面へ1タップで到達できること。

**車両切り替えの動線(複数車両・MVP)**:
- アプリは常に「選択中の車両」を1台持ち、一覧・グラフ・集計・入力の既定対象はすべて選択中の車両とする(選択状態は端末に保存し、次回起動時も維持)
- 各画面のヘッダに選択中の車両名を常時表示。タップで車両切り替えシート(S-11)を開き、**2タップで切り替え完了**
- 給油・メンテの入力画面にも対象車両を表示し、その場で変更可能(別車両への誤記録を防止)

### S-01 ホーム(ダッシュボード)【MVP】
- **目的**: 現状把握と入力への最短導線
- **表示項目**: 選択中の車両名(ヘッダ)、直近燃費(km/L)、平均燃費、今月の燃料費、直近のメンテ記録(1〜3件)、(フェーズ2)リマインダー警告 ※数値はすべて選択中の車両のもの
- **主な操作**: 「給油を記録」大ボタン → S-02へ / 「メンテを記録」ボタン → S-05へ / 車両名タップ → S-11(車両切り替え)

### S-02 給油入力【MVP・最重要画面】
- **目的**: 給油直後の最速入力(目標30秒・最小タップ数)
- **表示項目(入力欄)**:
  - 対象車両(初期値: 選択中の車両。タップで変更可)
  - 日付(初期値: 今日)
  - ODOメーター値(km)※対象車両の前回値をプレースホルダ表示
  - 給油量(L)
  - 金額(円)(**任意**)※**総額入力が既定**(レシート通りに入力)。入力された場合のみ単価(円/L)を自動計算して表示し、単価側からの入力も可
  - 満タンチェック(初期値: ON)
  - 給油所名(任意。前回値を初期表示)
  - メモ(任意)
- **主な操作**: 保存(**ODO・給油量の2項目の入力で保存可**。保存後は燃費を即時表示してホームへ)/ キャンセル
- **入力支援**: 数値欄タップで数値キーパッド起動。必須はODO・給油量の2つのみ

### S-03 給油履歴一覧【MVP】
- **目的**: 給油と燃費の履歴確認(選択中の車両の記録を表示)
- **表示項目**: 日付、給油量、金額、単価、燃費(km/L。積算計算中の行は「計算待ち」表示)、満タン区分 ※金額未入力の記録は金額・単価欄を「—」で表示
- **主な操作**: 行タップ → S-04(詳細・編集)/ 追加ボタン → S-02

### S-04 給油詳細・編集【MVP】
- **目的**: 記録の確認・修正・削除
- **表示項目**: S-02の全項目+算出燃費、前回給油からの走行距離 ※金額未入力の場合、金額・単価は「—」で表示
- **主な操作**: 編集して保存 / 削除(確認ダイアログ)

### S-05 メンテナンス入力【MVP】
- **目的**: 整備実施内容の記録
- **表示項目(入力欄)**: 対象車両(初期値: 選択中の車両。タップで変更可)、種別(オイル交換/タイヤ交換・ローテーション/車検/法定点検/バッテリー交換/ワイパー交換/その他 から選択)、日付(初期値: 今日)、ODO、費用、実施店舗(任意)、メモ(任意)
- **主な操作**: 保存 / キャンセル

### S-06 メンテナンス履歴一覧【MVP】
- **目的**: 整備履歴の確認(「前回オイル交換いつ?」に即答。選択中の車両の記録を表示)
- **表示項目**: 日付、種別、ODO、費用、店舗。種別フィルタ
- **主な操作**: 行タップ → 詳細・編集・削除 / 追加ボタン → S-05

### S-07 燃費グラフ【MVP(P1)】
- **目的**: 燃費推移の可視化(選択中の車両)
- **表示項目**: 燃費の折れ線グラフ(横軸: 給油日)、平均燃費ライン、期間切替(直近12回/半年/1年/全期間)
- **主な操作**: 期間切替、点タップで該当給油の詳細表示

### S-08 車両管理(一覧・登録・編集)【MVP】
- **目的**: 複数車両(車・バイク)の登録・編集・アーカイブ
- **表示項目**: 登録車両の一覧(**タイプ別アイコン(車/バイク)**・車両名・選択中マーク)。車両編集フォーム: 車両タイプ(車/バイク。初期値: 車)、車両名、メーカー(**プルダウン選択**)・型式(任意)、初度登録年月(任意。入力時は経過年月をライブ表示)、登録時ODO(任意)、燃料種別、タンク容量(任意)、車検満了日(任意)
- **主な操作**: 車両の追加 / 編集して保存 / アーカイブ(手放した車両の非表示。記録は保持)/ 行タップで選択中の車両に切り替え
- **メーカープルダウン(入力支援)**: 車両タイプに応じて候補リストを切り替える。「その他(手入力)」を選ぶと自由入力欄を表示
  - 車: トヨタ / ホンダ / 日産 / マツダ / スバル / 三菱 / スズキ / ダイハツ / レクサス / 主要輸入車(メルセデス・ベンツ、BMW、フォルクスワーゲン 等)
  - バイク: ホンダ / ヤマハ / スズキ / カワサキ / ハーレーダビッドソン / BMW / ドゥカティ / トライアンフ / KTM
- **備考**: 初回起動時は本画面(車両登録フォーム)から開始する

### S-09 設定・データ管理【MVP(P1)】
- **目的**: アプリ設定とバックアップ
- **表示項目/操作**: データエクスポート(JSON/CSV。全車両分を一括出力)、車両管理(S-08)への導線、(フェーズ2)インポート、(フェーズ2)リマインダー設定一覧

### S-10 リマインダー設定【フェーズ2】
- **目的**: メンテ種別ごとの次回時期ルール設定(車両ごと)
- **表示項目**: 種別、距離間隔(km)、期間間隔(ヶ月)、有効/無効。初期値として既定ルール(オイル交換 5,000km/6ヶ月、車検 24ヶ月 等。6.2参照)をセットし、ユーザーが変更可能
- **主な操作**: ルールの追加・編集・削除

### S-11 車両切り替えシート【MVP】
- **目的**: 選択中の車両の切り替え(各画面ヘッダから呼び出すボトムシート/ドロップダウン)
- **表示項目**: 車両一覧(**タイプ別アイコン(車/バイク)**、車両名、選択中マーク。アーカイブ済みは非表示)。車・バイクをアイコンでひと目で識別できること(アイコンの詳細デザインは画面設計書で定義)
- **主な操作**: 車両タップで切り替えて閉じる(**2タップで完了**)/ 「車両を追加」→ S-08へ

## 5. データ項目定義

すべてのレコードに共通で `id`(一意)、`createdAt`、`updatedAt` を持つ。
複数車両管理(F-14)はMVPに含むため、**全記録テーブルは `vehicleId` で車両に紐づける**。
また、アプリ設定として `selectedVehicleId`(選択中の車両ID)を端末に保存し、起動時に復元する。

### 5.1 車両(Vehicle)

| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| id | 文字列(UUID) | ○ | 車両ID |
| vehicleType | 列挙 | ○ | **car(車)/ motorcycle(バイク)**。初期値: car。一覧・切り替えUIのタイプ別アイコン表示に使用 |
| name | 文字列 | ○ | 表示名(例: ノート、ジムニー、CB400) |
| maker / model | 文字列 | - | メーカー・車種/型式。メーカーは文字列のまま保存(入力時は車両タイプに応じた主要メーカーのプルダウン+「その他(手入力)」で支援。S-08参照) |
| firstRegistrationYm | 年月 | - | 初度登録年月。設定時は S-08(車両一覧・編集フォーム)に初度登録からの経過年月「◯年◯ヶ月」を補足表示する |
| initialOdo | 数値(km) | - | 登録時点のODO(**任意**。燃費計算には使用しない。設定時はODOの入力チェック(逆行警告)・前回値ヒントの基準に使用。未設定の場合は基準なし = 最初の給油では逆行警告を出さない) |
| fuelType | 列挙 | ○ | レギュラー/ハイオク/軽油(初期値: レギュラー) |
| tankCapacity | 数値(L) | - | タンク容量(給油量の入力チェックに利用) |
| inspectionExpiry | 日付 | - | 車検満了日 |
| photoUpdatedAt | 日時 | - | 愛車の写真(F-22)の最終更新日時。**値があること = 写真が設定されていること**。画像本体は別に持つ(下記)。未設定なら写真なし |
| isArchived | 真偽 | ○ | 手放した車両の非表示用(初期値: false) |

**愛車の写真(F-22)の保持方法**:

| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| vehicleId | 文字列 | ○ | 対象車両ID(車両と1:1。写真は1台につき1枚) |
| blob | バイナリ | ○ | 画像本体(**Base64ではなくバイナリのまま保持**。IndexedDB がそのまま扱える) |
| mimeType | 文字列 | ○ | 通常 `image/jpeg` |
| byteSize / width / height | 数値 | - | 保存後のバイト数・寸法(容量表示・レイアウト用) |
| updatedAt | 日時 | ○ | 設定・差し替え日時(Vehicle.photoUpdatedAt と一致) |

- **画像本体は車両レコードと別テーブルに置く**。車両一覧は画面表示のたびに全車両を読むため、そこに数百KBの画像を同居させると一覧のたびに全画像を読み込むことになる。写真は表示する画面でだけ読み出す
- **保存前に自動で縮小・圧縮する**: 長辺1280px以内(元が小さければ拡大しない)、JPEG品質0.85。スマホの写真(3〜12MB)が概ね100〜300KBになる
- 取り込めるのは画像ファイルのみ。20MB超・画像以外・SVGは明確なエラーで弾く
- 撮影時の向き(EXIF)を反映してから保存する。再エンコードの結果、**EXIF(撮影位置=GPS を含む)は保存データに残らない**
- 車両をアーカイブしても写真は保持する

### 5.2 給油記録(FuelRecord)

| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| id | 文字列(UUID) | ○ | 記録ID |
| vehicleId | 文字列 | ○ | 対象車両 |
| date | 日付 | ○ | 給油日(初期値: 今日) |
| odo | 数値(km) | ○ | 給油時のODOメーター値 |
| fuelAmount | 数値(L・小数2桁) | ○ | 給油量 |
| totalPrice | 数値(円) | - | 支払金額(**任意**。入力する場合は総額入力が既定) |
| unitPrice | 数値(円/L) | - | 単価。**金額が入力された場合のみ**総額と給油量から自動算出して表示(単価側からの入力も可。保存時は両方保持。金額未入力なら両方 null) |
| isFullTank | 真偽 | ○ | 満タンか(初期値: true)。燃費計算の区切り判定に使用 |
| stationName | 文字列 | - | 給油所名(前回値を初期表示) |

- 履歴一覧(S-03)・詳細(S-04)では金額・単価欄を「—」で表示
- 費用集計(フェーズ2のF-16、ホームの「今月の燃料費」等)では金額なしの記録を集計対象外とし、その旨を集計画面に注記する

## 6. 主要ロジック仕様

### 6.1 燃費計算(満タン法)

※ 本ロジックは車・バイク共通(車両タイプによる分岐なし)。

- 基本式: **燃費(km/L) = 走行距離(km) ÷ 給油量(L)**
- 燃費は「満タン給油 → 次の満タン給油」の区間で確定する:
  1. 今回給油が **満タン** の場合: 直前の満タン給油を探し、`走行距離 = 今回ODO − 前回満タン時ODO`、`給油量 = 前回満タン以降の全給油量の合計(今回分を含む)` で計算
  2. 今回給油が **満タンでない**(部分給油)場合: 燃費は確定しない。一覧では「計算待ち」と表示し、給油量を次の満タン給油まで積算する
  3. 区間内の最初の記録(前に満タン給油が存在しない場合)は燃費を計算しない(基準が無いため)
- 記録の追加・編集・削除・満タンフラグ変更時は、影響する区間(前後の満タン給油の間)の燃費を再計算する
- 入力チェック(警告表示、保存はブロックしない):
  - ODOが直前の記録より小さい → 「走行距離がマイナスです」警告
  - 給油量がタンク容量(設定時)を超える → 警告
  - 算出燃費が 1〜60 km/L の範囲外 → 入力ミスの可能性を警告
- 平均燃費 = 対象期間の確定区間の(総走行距離 ÷ 総給油量)※各区間燃費の単純平均ではない

### 6.2 リマインダー判定【フェーズ2】

- 次回目安 = 同種別の最新メンテ記録の(ODO + intervalKm)/(日付 + intervalMonths)
- 現在ODOの推定: 対象車両の最新の給油記録のODOを「現在の走行距離」とみなす
- 距離・期間の両方が設定されている場合は早く到達する方を採用
- 通知方式: **アプリ内表示のみ**(ホームの警告表示)。端末プッシュ通知は行わない(フェーズ3で必要になった場合のみ検討)
- 初期ルール既定値(車両追加時にセット。ユーザーが変更・無効化可能):

| 種別 | 距離間隔 | 期間間隔 |
|---|---|---|
| オイル交換 | 5,000km | 6ヶ月 |
| オイルフィルタ交換 | 10,000km | 12ヶ月 |
| タイヤローテーション | 5,000km | - |
| 車検 | - | 24ヶ月 |
| 法定点検 | - | 12ヶ月 |
| バッテリー交換 | - | 36ヶ月 |
| ワイパー交換 | - | 12ヶ月 |

## 8. 技術スタック(確定: PWA)

> 2026-07-03 ユーザー確認により **PWA案で確定**。iPhone・Android の両方から同一URLをホーム画面に追加して利用する。
> 懸念だったiOSの通知制約は、リマインダーを「アプリ内表示のみ」(F-12)とする決定により解消。

### 8.1 選択肢の比較

前提: 個人開発・スマホ利用が主・開発環境は Windows 11・MVPはオフラインのローカル保存のみ(サーバ不要)。

| 観点 | **PWA(Web)** | Flutter | React Native(Expo) | ネイティブ(Kotlin/Swift) |
|---|---|---|---|---|
| Windowsでの開発 | ◎ ブラウザのみで完結 | ○ Android可 / **iOSビルドはMacが必要** | ○ ExpoでiOS実機確認は可能だがストア配布はMac/EAS依存 | △ iOS開発は不可 |
| 配布(個人利用) | ◎ URLを開いて「ホーム画面に追加」だけ。ストア審査・年会費(Apple $99/年)不要 | △ ストア経由 or 手動インストール | △ 同左 | △ 同左 |
| オフライン動作 | ○ Service Worker + IndexedDB で十分実現可 | ◎ ローカルDB(SQLite等) | ◎ 同左 | ◎ |
| プッシュ通知 | △ iOSはホーム画面追加したPWAで対応(iOS 16.4+)だが制約あり | ◎ | ◎ | ◎ |
| 開発・修正の速さ | ◎ デプロイ即反映。学習コスト最小 | ○ Dart学習が必要 | ○ | △ 2言語 |
| PCからの閲覧(将来) | ◎ そのまま使える | △ 別途Web対応 | △ 同左 | ✕ |
| 主なリスク | ストレージ削除でデータ消失(エクスポートで軽減)/ 通知の制約 | Mac無しでiOS配布不可 | ビルド環境の複雑さ | コスト過大 |

### 8.2 採用: **PWA(React + TypeScript + Vite、IndexedDB(Dexie.js)、ホスティングは静的サイト)**

**理由:**
1. **Windows開発環境と完全に相性が良い**: iPhoneを使う場合でもMac不要。ブラウザとエディタだけで開発・デバッグ・配布まで完結する
2. **個人利用の配布に最適**: ストア審査・開発者登録費用が不要。URLにアクセスして「ホーム画面に追加」すればアプリとして使える。修正も即座に反映される
3. **本アプリの要件に必要十分**: 中核要件(オフライン入力・ローカル保存・グラフ表示)は Service Worker + IndexedDB で完全に満たせる。カメラ・GPS等のネイティブ機能はMVPでは不要
4. **将来の拡張と地続き**: PC閲覧はそのまま動く。クラウド同期(フェーズ3)もWeb技術の延長で追加できる。開発チーム(frontend/backend エージェント)の知識が最も活きるスタック
5. **最大の弱点(通知・データ消失)には対策がある**: リマインダーはアプリ内表示(F-12)で運用することが確定済み(プッシュ通知F-13はフェーズ3以降の検討事項)。データ消失はエクスポート機能(F-11)と Storage永続化APIで軽減する
6. **iPhone・Android両対応が同一コード・同一URLで実現できる**: OSごとのビルド・配布が不要で、両端末で常に同じ最新版が使える

**推奨構成(詳細):**

| レイヤ | 技術 | 備考 |
|---|---|---|
| 言語/FW | TypeScript + React | エコシステム最大。型で計算ロジックの品質を担保 |
| ビルド | Vite + `vite-plugin-pwa` | Service Worker/マニフェスト生成を自動化 |
| ローカルDB | IndexedDB + Dexie.js | スキーマ管理・マイグレーションが容易 |
| グラフ | Recharts(または Chart.js) | 燃費推移の折れ線に十分 |
| テスト | Vitest | 燃費計算・リマインダー判定の単体テスト必須 |
| ホスティング | **GitHub Pages(第一候補)** | HTTPS必須(PWA要件)。無料。実装時に再確認(代替: Cloudflare Pages / Vercel) |
| 状態管理 | まずは React標準(Context/hooks)で開始 | 規模的に外部ライブラリ不要 |

**次点案**: 「毎日必ずプッシュ通知が欲しい」「ウィジェットが欲しい」等ネイティブ要件が強まった場合は **Flutter(Android先行)** を次点とする。ただしiOS配布にMacが必要になる点に注意。
